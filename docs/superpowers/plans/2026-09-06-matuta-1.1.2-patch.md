# Matuta 1.1.2 패치 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 알람이 조용히 사라지는 세 가지 경로를 막는다 — 앱이 죽는 것, 알람이 안 꺼지는 것, 재부팅 후 앱이 안 뜨는 것.

**Architecture:** 크래시는 App 구조체가 `@MainActor` 객체를 `@State`로 들고 있어서 SwiftUI가 씬 그래프를 갱신할 때 동적 액터 검사가 터지는 문제다. 상태 소유를 App에서 걷어내 싱글턴 + 얇은 루트 뷰로 옮긴다. 나머지 둘은 국소 수정이다.

**Tech Stack:** Swift 6.3, SwiftUI, AppKit, ServiceManagement (`SMAppService`), 기존 SwiftPM 구성 유지

## Global Constraints

- 배포 대상 macOS 14.0 이상, 비샌드박스, Developer ID 서명 + 공증
- 이 패치에서 **기능을 추가하지 않는다.** 로그인 자동 실행은 "앱이 안 떠 있으면 안 울린다"는 실패 경로를 막는 것이므로 신뢰성 수정으로 취급한다
- 설계 원칙 유지: 신뢰성은 설정이 아니라 동작이다. 설정 창에 항목을 늘리는 것은 로그인 자동 실행 하나만 허용한다
- 모든 사용자 노출 문자열은 `LocalizedText` 키를 거친다. 뷰에 한국어·영어 리터럴을 직접 넣지 않는다
- 각 태스크 종료 시 `swift build` 무경고, `swift test` 전부 통과

## Task 1: App에서 `@MainActor` 상태 소유를 걷어낸다

크래시의 근본 수정이다.

현재 `MatutaApp`은 `@MainActor` 객체 둘(`AlarmListModel`, `LanguageSetting`)을 `@State`로 들고, 세 씬의 콘텐츠 클로저와 `menuBarLabel` 계산 프로퍼티가 그것을 직접 만진다. 그래서 SwiftUI가 씬 그래프를 갱신할 때마다 동적 액터 검사가 들어가고, 그 검사가 터진다.

**뷰의 `body`는 메인 액터 격리가 확실하다.** 상태 접근을 뷰 안으로 옮기면 그 검사가 아예 생기지 않는다.

`LanguageSetting`은 이미 `static let shared` 싱글턴이고 `NightstandWindow`·`AlarmOverlayWindow`가 `@State` 없이 직접 쓴다. App만 불필요하게 `@State`로 감싸고 있었다. `AlarmListModel`도 같은 모양으로 맞춘다.

## Task 2: 외부 앱을 열 때 포커스를 뺏기지 않게

유튜브 링크 알람에서 스페이스바를 눌러도 백업음이 안 꺼지는 문제의 수정이다.

원인은 이렇다. `fire()` 는 오버레이를 띄워 키 창으로 만든 **뒤에** 비동기 작업이 브라우저를 연다. `NSWorkspace.shared.open(url)` 은 기본적으로 대상 앱을 전면으로 가져오므로 브라우저가 포커스를 가져간다. 앱에 전역 키 모니터가 없어 오버레이는 키 창일 때만 스페이스바를 받는다. 그래서 스페이스는 브라우저로 가고 — **스페이스는 YouTube 의 재생/일시정지 단축키라 영상만 멈춘다** — `dismissFiring()` 은 호출되지 않아 백업음이 계속 울린다.

오버레이는 `.screenSaver` 레벨이라 브라우저를 어차피 시각적으로 덮는다. 활성화해봐야 보이지도 않으므로 얻는 것 없이 포커스만 뺏기고 있었다.

- [ ] **Step 1: 활성화하지 않고 여는 공용 헬퍼를 만든다**

```swift

///
/// 기본 `NSWorkspace.open(_:)` 은 대상 앱을 활성화하므로 알람 오버레이가
/// 키 창 지위를 잃는다. 그러면 스페이스바가 브라우저로 가고(YouTube 에서는
/// 재생/일시정지로 먹힌다) 알람이 꺼지지 않는다. 오버레이는 .screenSaver
/// 레벨이라 어차피 화면을 덮으므로 활성화해서 얻는 것이 없다.
@MainActor
```

```swift
/// 로그인 항목 등록을 감싼다. 시스템을 읽고 쓰기만 하고 판정은 하지 않는다.
```
